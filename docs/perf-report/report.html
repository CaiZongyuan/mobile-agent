性能分析与结论

  • 端到端 21.8s 完成「冷启动 → 进入多多买菜 → 关弹窗 → 肉蛋分类 → 解析出鸡蛋」完整闭环，其中真正落在设备上的主动操作仅 9.4s（43.0%），其余为渲染等待与轮询。
  • 最大单项是 adb daemon 冷启动（5087 ms），仅出现在会话首命令；常驻会话或复用连接可消除。
  • 固定缓冲等待合计 7.7s（首页 2.0s + WebView 2.5s + 弹窗 1.2s + 分类 2.0s），是最大的可优化项——用「元素出现即继续」的事件驱动轮询替代固定 sleep，预计可压缩 30–50%。
  • 无障碍树是感知主通道：5 次读取共 2034 ms，每次约 407 ms，明显快于截图 + OCR 路线（截图单张就要 838 ms 且还需识别）；且树直接给出 bounds，坐标点击零计算开销。
  • 点击命中率高：3 次触控全部按预期生效（入口→弹窗关闭→分类切换均有状态回读验证），归因于「树定位 + 最小面积匹配」策略，避免了整屏 WebView 根节点的误匹配。
  • 风险项：连续快速滚动浏览会触发拼多多安全验证（前一会话实测）；本报告流程未触发。滑动/滚动操作建议控制频率并加随机抖动。
